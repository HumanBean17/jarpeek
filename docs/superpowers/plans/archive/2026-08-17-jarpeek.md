# jarpeek v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `jarpeek` — an npm-distributed tool (MCP server + CLI over one core) giving AI agents context-frugal navigation into JVM dependency sources: resolve the dependency set, index declarations, serve outlines/member slices/resources with provenance, decompile with bundled CFR.

**Architecture:** Layered pure-TypeScript: resolvers (Gradle → Maven → CacheScan, plus JDK pseudo-artifact) → indexer (own Java/Kotlin lexers, own zip reader, own class-file reader) → plain-file index (NDJSON shards keyed by coordinates, FQN directory, project manifest) → query layer (find_class, outline, read_member, read_source, read_resource, search_symbols, resolve/status/where, miss protocol) → two transports (CLI, MCP stdio) + `init`/`prime` harness integration.

**Tech Stack:** Node ≥ 20 (ESM, TypeScript strict), vitest, commander, @clack/prompts, @modelcontextprotocol/sdk, bundled CFR 0.152 invoked via `java -jar`. JDK 25 available locally for fixture building and decompile tests; Maven 3.9 available; **no system Gradle** (Gradle e2e tests are env-gated).

## Global Constraints

Copied from the spec — every task implicitly includes these:

- **Single delivery event**: everything a running jarpeek needs arrives with `npm install jarpeek` — CFR jar bundled in the tarball. **No runtime downloads, ever.**
- **Zero native modules**: no better-sqlite3, no tree-sitter — nothing requiring node-gyp or platform prebuilds. (Dev dependencies like vitest are exempt; the *published runtime* is pure JS.)
- **No postinstall scripts**: nothing compiles or fetches at install time. No `postinstall`/`preinstall`/`install` scripts may ever appear in package.json.
- **Runtime requirements**: Node.js ≥ LTS (engines `>=20`). JVM required only for CFR decompilation; everything else works without one.
- **Allowed npm runtime dependencies**: pure-JS only — `@modelcontextprotocol/sdk`, `commander`, `@clack/prompts` (all arrive by the same install). Nothing else.
- **Platforms**: Windows, Linux, macOS first-class and uniform. All paths via Node `path`/`os` APIs; Gradle wrapper invoked as `gradlew.bat` on Windows; jar entry names always `/`-separated.
- **Provenance on every query response**: `"source" | "decompiled" | "signature"` — degraded answers self-describe; responses never lie.
- **Parsing/storage are own implementations**: hand-written Java/Kotlin declaration lexers, own zip central-directory reader (incl. zip64 — JDK `src.zip` needs it), own class-file reader, own NDJSON index. Lexer degradation is graceful: exotic syntax yields a missing member or imprecise range, never a crash.
- **Language**: all user-facing strings in English. Tests, code comments and identifiers in English.
- Package lives in repo subdir `jarpeek/` (repo root holds docs). Repo: `jvm-src`, remote `origin` = `github.com:HumanBean17/jarpeek.git`, base branch `main`.
- Test commands below assume CWD = `jarpeek/`. Full suite: `npm test` (vitest run). Typecheck: `npm run typecheck`.

    - `interface Declaration { fqn: string; file: string; selector: string; kind: DeclKind; visibility: Visibility; static: boolean; deprecated: boolean; signature: string; lineStart?: number; lineEnd?: number; javadocStart?: number; receiverType?: string; modifiers?: string[]; platform?: "expect" | "actual"; }` — `fqn` = declaring class FQN; `file` = `/`-separated entry or repo-relative path; `selector` = member name (or simple class name for class records); `signature` = one-line human-readable declaration.
    - `interface DependencyArtifact { coordinates: string; configuration?: string; kind: "external" | "module" | "jdk" | "cache-scan"; binaryJar?: string; sourcesJar?: string; sourceDir?: string; classesDir?: string; provenance: Provenance; noDecompile?: boolean; warnings: string[]; }`

  - `util/lockfile.ts`: `withLock<T>(cacheDir: string, fn: () => Promise<T>): Promise<T>` — creates `<cacheDir>/jarpeek.lock` with `O_EXCL` (flag `"wx"`) containing `<pid>\n<iso-timestamp>`; on `EEXIST` with lock mtime older than 10 minutes → steal (unlink + retry once); other EEXIST → retry loop max 50 × 100ms then throw `LockTimeoutError`; always release (unlink) in finally. Read paths elsewhere must NOT take this lock.
  - `util/exec.ts`: `runWithTimeout(cmd, args, opts)` → `Promise<{ stdout: string; stderr: string; code: number | null }>`; opts `{ timeoutMs = 120000, cwd?, env?, maxBuffer? }`; on timeout kills the child (SIGKILL after SIGTERM grace 2s) and rejects with `TimeoutError`; spawn failure (ENOENT) rejects with `SpawnError` (both `Error` subclasses, `name` set); non-zero exit is a resolved value, not a rejection.
  - `util/lines.ts`: `splitLines(text: string): string[]` (splits `\n`, strips trailing `\r` — CRLF-safe); `sliceLines(text: string, from: number, to: number): { lines: string[]; startLine: number; endLine: number; clamped: boolean }` — 1-based inclusive; out-of-range bounds clamp to file bounds with `clamped: true`; empty text yields empty lines.

  - Fixture source contract (these exact declarations must exist in the fixtures and drive goldens):
