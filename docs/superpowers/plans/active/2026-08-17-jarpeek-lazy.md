# jarpeek Lazy Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace jarpeek's index-first core with a lazy core: resolve writes only a tiny manifest; queries read zip central-directory listings in memory and parse exactly one file per call; no declaration index, no per-artifact progress output, stderr capped at 3 lines.

**Architecture:** A new `ListingService` maps artifacts → zip entry names (process memory only, validated by mtime+size). A new locate layer (`locateClass`) finds an FQN's artifact via listings and parses that single file with the existing lexers/class-file reader. CFR decompilation stays per-class with an in-process memo. The index subsystem (IndexStore, indexer, shards, lockfiles, jimage, unpacked sources) is deleted. Spec: `docs/superpowers/specs/active/2026-08-17-jarpeek-lazy-design.md`.

**Tech Stack:** TypeScript (Node ≥ 20.12), pure-TS zip/classfile/lexer parsers, bundled CFR 0.152, commander CLI, MCP SDK, vitest.

## Global Constraints

- Zero native npm modules; zero runtime downloads; no postinstall scripts (locked v1 policy, unchanged).
- The manifest (`.jarpeek/manifest.json`) is the only derived state ever written to disk. Forbidden: index shards, entry caches, decompile caches on disk, unpacked sources, jimage extraction. (Transient CFR temp files under the OS tmpdir are allowed.)
- Queries auto-resolve (missing or stale manifest) but never index; the explicit `resolve` command also never indexes.
- stdout carries the answer only. stderr ≤ 3 lines per CLI invocation (1 optional resolve-notice + ≤ 2 deduped warning lines; overflow aggregates). No per-artifact output anywhere.
- Misses are answers: unknown classes/artifacts answer with suggestions and exit 0; only malformed selectors and IO/usage errors are fatal (exit 1).
- Every task ends with `npm run typecheck` AND `npm test` green, then a commit. Tests are offline; network e2e self-skips unless `JARPEEK_E2E=1`.
- Never edit fixture jars under `test/fixtures/jars` by hand — they are generated by `node scripts/build-fixtures.mjs`.
- Repo convention: create a beads issue (`bd create --type=task`) before starting each task; `bd close <id>` after its commit.
- The old `DependencyArtifact` fields (`provenance`, `warnings`, `sourceSig`, `classesDir`) become optional in Task 4 and are deleted in Task 13 — never add new readers of them.

### Task 2: ListingService (`src/core/listing.ts`)

**Files:**
- Create: `src/core/listing.ts`
- Test: `test/unit/listing.test.ts`

**Interfaces:**
- Consumes: `listZipEntries`, `readZipEntry`-adjacent types (`ZipEntry` from `src/parse/zip.ts`), `walkFiles`, `isSourceEntry` (`src/index/walk.ts`), `DependencyArtifact` (`src/core/types.ts`).
- Produces:
  - `ClassEntry { fqn: string; entry: string }` — `fqn` derived from the entry path: `a/b/C.class` → `a.b.C`; `a/b/Outer$Inner.class` → `a.b.Outer$Inner`; source entries drop the extension (`a/b/C.java` → `a.b.C`, `.kt` likewise).
  - `ArtifactListing { coordinates: string; source: "binary" | "sources" | "sourceDir"; classes: ClassEntry[]; entries: readonly ZipEntry[]; stamp: string; unreadable?: string }` — `entries` is the raw listing for binary/sources zips (empty array for `sourceDir`); `stamp` identifies the backing version (`"${mtimeMs}:${size}"` of the jar file, or of the sourceDir for `sourceDir`); `unreadable` set when the jar/dir could not be read (classes/entries then empty).
  - `class ListingService` with `constructor(opts?: { listZip?: typeof listZipEntries; stat?: (path: string) => { mtimeMs: number; size: number } })` (both injectable for tests), and:
    - `listing(artifact: DependencyArtifact): Promise<ArtifactListing>` — picks the first existing backing in order `binaryJar` → `sourcesJar` → `sourceDir`; caches by coordinates and re-lists when `stamp` changes; a cached unreadable result is likewise re-tried on stamp change.
    - `invalidate(coordinates: string): void` — drops the cache entry (used by tests).
  - Class-entry derivation rules: binary listings keep `isClassEntry` entries; source listings keep `isSourceEntry` entries; both drop entries whose SIMPLE NAME — the entry-name segment after the last `/`, then after the last `$` or `.` — does not start `[A-Za-z_]` (the spec's anonymous/local-class filter for ENTRY names). Implement it as a dedicated helper in listing.ts (e.g. `isIndexableEntryName(entryName: string): boolean`); do NOT reuse `isIndexableClass` from records.ts — it filters dotted PARSED fqns (where `$` was already mapped to `.` by the class-file reader) and does not reject raw entry names like `Outer$1`. `sourceDir` listings walk with `walkFiles(dir, isSourceEntry, prune=true, warnings)` and build `ClassEntry` from each relpath, `source: "sourceDir"`, `entries: []`.
  - An artifact with no existing backing returns `{ source: "binary", classes: [], entries: [], stamp: "", unreadable: "no jar or source dir" }`-shaped result (source field of an empty backing: use `"binary"` with `unreadable` set — the `source` discriminator is meaningless when unreadable).

### Task 5: Locate layer (`src/core/query/locate.ts`)

**Files:**
- Create: `src/core/query/locate.ts`
- Test: `test/unit/locate.test.ts`

**Interfaces:**
- Consumes: `ListingService` + `ArtifactListing` (Task 2), `recordsFromSourceText`/`recordsFromClassBytes`/`isIndexableClass` (Task 1), `readTextEntry`/`readZipEntry` (`src/parse/zip.ts`), `readFileSync`, `LookupMissError` (`src/core/query/outline.ts`), `Manifest` (`src/index/manifest.ts`), `DependencyArtifact`, `Declaration`, `Provenance`.
- Produces:
  - `interface LocateDeps { listings: ListingService; manifest(): Promise<Manifest | null> }` — `QueryContext` will satisfy this structurally from Task 6.
  - `classFamily(recordFqn: string, target: string): boolean` — true when equal, or `recordFqn` is a direct-or-deeper nested member via either separator: `recordFqn === target + "." + rest` or `recordFqn === target.replace(/\./g, ".") + "$" + rest` (i.e. starts with `target + "$"` or `target + "."`, at least one further segment). Dot- and dollar-nesting match each other.
  - `interface LocatedClass { artifact: DependencyArtifact; entry: string; records: Declaration[]; provenance: Provenance }` — `entry` = jar entry name or sourceDir relpath the records were parsed from; `records` = the class's own record (class row) + its member records +, when `includeNested`, one class-kind row per directly nested class; `provenance` is `"source"` for sources/sourceDir backings, `"signature"` for binary (locate never decompiles).
  - `interface LocateResult { winner: LocatedClass; alternatives: Array<{ coordinates: string }>; degraded: string[] }`
  - `async function locateClass(deps: LocateDeps, fqn: string, opts?: { includeNested?: boolean }): Promise<LocateResult>` — default `includeNested: true`. Iterates manifest artifacts in order; per artifact, `listings.listing(artifact)`:
    - binary backing: candidate entry = `fqn.replaceAll(".", "/") + ".class"`; hit when the raw `entries` array contains that exact name.
    - sources backing: candidates `…+ ".java"` then `…+ ".kt"`; hit on exact name, else a unique entry whose name ends with `"/" + candidate` (the same suffix rule `read-source.ts:169-171` uses today); ambiguous suffix (2+ matches) counts as a miss for that artifact.
    - sourceDir backing: candidate relpath = `fqn.replaceAll(".", "/") + ".java"` / `".kt"` matched against `classes` entries by exact entry name.
    - Records on hit: sources/sourceDir → read the entry text (`readTextEntry` / `readFileSync(join(sourceDir, entry))`) → `recordsFromSourceText` → keep records where `classFamily(record.fqn, fqn)` (members carry the class fqn and pass as equal). Binary → `readZipEntry` → `recordsFromClassBytes` → keep equal-fqn records (class row + members). Nested (binary only): listing entries whose name is `fqnInternal + "$" + ident` with `ident` containing no `$` and starting `[A-Za-z_]` (Task 2's entry-name rule) → one class-kind record each (their class row only). Nested in source files comes free from the family filter — restrict nested rows to class-kind records (`isClassKind` from outline.ts).
    - First manifest-order hit wins; later hits become `alternatives` (coordinates only). No hit in any artifact → throw `LookupMissError(fqn)`.
    - `degraded`: one aggregated string when some artifacts were unreadable: `"${n} artifacts unreadable (${first 3 coordinates})"`, only when n > 0; plus `"${n} entries failed to parse"` aggregated identically when per-entry reads/lexes threw.
  - `async function recordsForArtifact(deps: LocateDeps, artifact: DependencyArtifact): Promise<ArtifactRecords>` — added in Task 9 (declared here for the module's purpose statement only; do not implement yet).
